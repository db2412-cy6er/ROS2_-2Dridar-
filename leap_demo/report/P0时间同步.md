## 2. 具体改动清单

### 2.1 主板固件 `leap_ros/leap_low_v1`

#### a) `components/lsm6ds3_driver/lsm6ds3_driver.cpp` / `.h`
- 新增量程/灵敏度常量并写入寄存器：
  - `CTRL1_XL(0x10)=0x48`：104Hz、±4g；
  - `CTRL2_G(0x11)=0x44`：104Hz、±500dps；
  - `kGyroSensitivityDpsPerLsb = 17.5/1000`、`kAccSensitivityGPerLsb = 0.122/1000`；
  - `CalibrateGyro()` 与 `Update()` 共用同一组常量（原 ±250/±2g 的 8.75 / 0.061 已删除）。
- **删除陀螺仪死区**（原 `kGyroDeadzone=0.2` 对 gyro_x/y/z 的钳位整段移除）。
- `Update()` 在 `ReadRegisters()` 成功后**立即**记录 `sample_us_ = esp_timer_get_time()`（新增成员 + `GetSampleUsUs()`），互补滤波 dt 也以它为准。含义：这一组 12 字节原始数据被读出的时刻。

#### b) `main/msg/imu_msg.h`
- `ImuMsg` 新增 `uint64_t sample_us`（采样时刻，us）与 `uint32_t sample_seq`（每采一次自增）。

#### c) `main/tasks/sensors/imu_task.cpp`
- 循环从 `vTaskDelay(20ms)` 改为 **`vTaskDelayUntil` 固定 10 ms**（避免累计漂移）；
- 每次采样后填充 `msg.sample_us = imu.GetSampleUsUs()`、`msg.sample_seq = ++sample_seq`。

#### d) `main/tasks/network/microros_task.cpp`
- 发布定时器 **20ms → 10ms**，`spin_once(20)` → `spin_once(10)`；
- 节奏：`/imu` 每 tick(~100Hz)；`/odom` 奇数 tick(50Hz)；`/scan`、`/battery_state` 每 10 tick(10Hz)；
- `/imu` 时间戳：只在 `rmw_uros_epoch_synchronized()` 为真时，按
  `ros_delta_ns = rmw_uros_epoch_nanos() - esp_timer*1000`、`stamp = sample_us*1000 + ros_delta_ns`
  打戳；未同步时 **stamp=0 并每秒 WARN**，绝不静默切到本地单调时间；
- 用 `sample_seq` 去重：同一份样本不会以两条不同 ROS 消息重复发布；
- `/imu` 只发原始 acc/gyro（rad/s、m/s²）；orientation 保持恒等，
  `orientation_covariance[0] = -1`（互补滤波只留在驱动内部供底盘控制用）；
- 同步时把 `ros_delta_ns` 通过新接口 `camera_i2c_client_set_ros_offset()` 喂给摄像头同步链路；未同步时 `camera_i2c_client_clear_ros_offset()`。

#### e) `components/camera_i2c_client/camera_i2c_client.h` / `.cpp`（主板侧）
- 新增 `camera_i2c_client_set_ros_offset(int64_t)` / `camera_i2c_client_clear_ros_offset()` / `camera_i2c_client_run_time_sync()`；
- `camera_task` 每 ~3 s 发起一轮 `SYNC`（5 组、取写事务耗时最短一组）→ 估计 `off_cam_main_us = t_write_end(main) - ts_cam(camera)`；
- 合成 `ROSOFF <ns>`（`rosoff = off_cam_main_us*1000 + ros_delta_ns`）写入摄像头；摄像头 hold 时会忽略，保证录制期间映射不变。

### 2.2 摄像头固件 `leap_cam`

#### a) `main/i2c_slave_comm.h` / `.c`
- 新增时间同步状态与访问器：
  - `camera_time_sync_set_hold(bool)` / `camera_time_sync_is_held()`
  - `camera_time_sync_get_rosoff(int64_t*)`
  - 内部用 `portMUX_TYPE` 保护 64 位 `rosoff_ns` / `last_rx_us`。
- RX 完成 ISR 里记录 `s_last_rx_us = esp_timer_get_time()`（该 I2C 写事务完成瞬间的摄像头本地时间）。
- 新命令：
  - `SYNC` / `TSYNC` → 回 `{"ok":true,"status":"sync","ts":<last_rx_us>}`；
  - `ROSOFF <ns>` → 保存映射（hold 时忽略，回 `rosoff_held`）。

#### b) `main/web_mjpeg.c`
- 每个 MJPEG part 新增 3 个头：
  ```
  X-Frame-Id: <连接内递增>
  X-Capture-Timestamp-Us: <fb->timestamp 换算 us>
  X-Capture-Ros-Time-Ns:  <capture_us*1000 + rosoff_ns>（未同步为 0）
  ```
- 采集时间取 `fb->timestamp`（驱动在帧采集起始写入的 esp_timer 时间，非发送时间）；若驱动返回 0 则回退为拿到 fb 后立即打点。

#### c) `main/web_config.c`
- 新增端点（配置服务器 80 端口）：
  - `GET /api/sync/hold`、`GET /api/sync/release`（冻结/恢复 Camera→ROS 映射）
  - `GET /api/sync/status`（返回 held、rosoff_valid、rosoff_ns）
- `max_uri_handlers` 6→10。

#### d) `main/CMakeLists.txt`
- REQUIRES 增加 `esp_timer`（web_mjpeg/i2c_slave_comm 需 `esp_timer.h`）。

### 2.3 PC 端 `~/semantic_slam_ws/src/leap_camera_bridge`（新建包）

- `camera_http_bridge` 节点（ROS2 Humble / ament_python / Python3）：
  - 拉取 `http://<cam>:81/`，按 boundary 解析 part 头与 JPEG；
  - 发布 `/camera/image_raw`（Sensor Data QoS，best-effort，`frame_id=camera_optical_frame`，stamp 用 `X-Capture-Ros-Time-Ns`）；
  - **stamp=0 + 每秒 WARN，绝不回退成 PC 接收时间**；
  - 发布 `/camera/camera_info`（transient-local；内参未标定前为 800×600 默认，标定后从 `camera_info_yaml` 加载）；
  - ROS2 service `~/sync_hold`（`std_srvs/SetBool`）调摄像头 hold/release。
- `check_p0_time` 工具：离线 rosbag2（或 `--live N`）检查 IMU 频率、时间单调性、Cam-IMU 最近邻时差统计。

## 3. 改动后体现在哪（可观测现象）

| 现象 | 改动前 | 改动后 |
|---|---|---|
| `ros2 topic hz /imu` | ~50 Hz | ~95–105 Hz |
| /imu stamp | 发布时刻（定时器回调打点） | 采样时刻（驱动寄存器读取完成瞬间），严格单调 |
| /imu orientation | 互补滤波四元数，cov=0 | 恒等四元数，`orientation_covariance[0]=-1` |
| 未同步时段 | 本地单调时间直接当 ROS 时间 | stamp=0 + WARN，杜绝时间断层 |
| /imu 重复样本 | 相位漂移时可能重复/丢弃 | `sample_seq` 去重，不重复发同一份样本 |
| /odom /scan /battery | 与 /imu 同一 20ms 节奏 | odom 50Hz、scan/battery 10Hz，/imu 单独 ~100Hz |
| MJPEG 每帧 | 只有 JPEG | 带 X-Frame-Id、X-Capture-Timestamp-Us、X-Capture-Ros-Time-Ns |
| 摄像头时间 | 无 | fb->timestamp 原始时间（DMA 起始）+ 同步后 ROS epoch 双轨保留 |
| Camera↔Main | 只有 STATUS/WIFI 命令 | 主板每 ~3s SYNC，写 ROSOFF；hold 冻结 |
| /camera/image_raw | 不存在 | bridge 发布 800×600，stamp=ROS 时间 |
| /camera/camera_info | 不存在 | transient-local 发布，标定后从 yaml 加载 |

## 7. P0.1 实机 60Hz 排障记录（2026-09-05）

### 7.1 现象
- 烧录 v2 后：`ros2 topic hz /imu` 仅 ~60Hz（min 2ms / max 77ms / std ~10ms）；
- 摄像头链路正常（`CAMERA_I2C: Time sync ...` 每 ~3s 一轮，ROSOFF 已写入）。

### 7.2 排障数据
| 测试 | 结果 | 结论 |
|---|---|---|
| /imu 单独 | 60Hz | 非旧固件（旧 20ms 应为 50Hz） |
| 四话题同测 | imu 60 / odom 30 / scan 6 / battery 6 | 全部话题精确 ×0.6 |
| tcpdump 20s | 2033 包 ≈102 包/s；包长 332/732/1512/92/13B | imu/odom/scan/battery 各 1 条/包，发送≈交付，链路无丢 |
| ping | 0% loss，avg 6.8ms | Wi-Fi 无系统性丢包 |

**关键推导**：0.6×(100+50+10+10) ≈ 102 包/s ≈ 实测包数，即**所有话题都只按 60% 节奏发出且全部被交付** → 瓶颈在主控单一发布任务内部，不在 Wi-Fi/Agent/PC。

### 7.3 根因（代码级确认）
`rmw_microxrcedds_c/src/rmw_publish.c`：
```c
if (UXR_BEST_EFFORT_STREAM == stream) {
    uxr_flash_output_streams(...);            // best-effort：非阻塞
} else {
    uxr_run_session_until_confirm_delivery(   // reliable：阻塞等 Agent ACK，超时 1000ms
        session, custom_publisher->session_timeout);
}
```
odom/scan 原用**默认 QoS=RELIABLE**，其 ACK 等待发生在跑 10ms 定时器的同一 `microros_task` 里。每次 odom reliable 发布阻塞到 Agent 回 ACK（Wi-Fi RTT ~7ms，抖动大、最大近 1000ms 超时），2-tick 周期被拉长到 ~33ms → 等效 ~16.7ms/拍 → 全话题 ×0.6（对应 scan max 612ms、imu max 182ms 的大洞）。

### 7.4 修复（v3，待烧录）
1. **odom/scan 发布 QoS 改 best-effort**（与 imu/battery 一致，全部 `rmw_qos_profile_sensor_data`）——根因修复；
2. `/imu` 每样本调用 `camera_i2c_client_set_ros_offset` 改为 **50ms 节流 + trylock（非阻塞）**，消除与摄像头时间同步抢锁造成的尖峰；
3. 摄像头时间同步降负载：周期 3s→**10s**、组数 5→**3**、读延迟 10→**5ms**（单次持锁 ≤55ms→~15ms）。

涉及文件：`microros_task.cpp`（QoS、节流）、`camera_i2c_client.{h,cpp}`（trylock 变体、降频）。

### 7.5 构建与待验证
- `ninja .../leap_low_v1` EXIT:0，新 `build/merged-binary.bin` 已生成（用户手动烧录，不使用 flash 指令）。

### 7.6 根因再定位与 v5 修复（FreeRTOS_HZ=100 / 等值超时）
- 诊断固件(v5)数据：`DIAG 5s: ticks=250 imu=250 odom=125 scan=25 battery=25 cb_avg_us=2989 cb_max_us=6174`，`ros2 topic hz /imu≈50Hz`。
  - `cb_avg_us≈3ms`：回调不慢，排除发布/发送阻塞；
  - `ticks=250/5s=50Hz`：**rcl_timer 配置 10ms 却只触发 ~50Hz**，全话题按 tick 比例 50/25/5/5 一致——节拍层问题，非负载问题。
- 实锤：`sdkconfig` 中 `CONFIG_FREERTOS_HZ=100`（10ms/tick），而项目 `sdkconfig.defaults` 意图是 **1000**（1ms/tick）。10ms 周期 == 1 tick，rcl_wait 用户超时(10ms)==定时器剩余(10ms) 走等值路径，实际每 2 tick 才触发一次 → 50Hz。
- v5 修复（已编译，EXIT:0，待烧录）：
  1. `sdkconfig`：`CONFIG_FREERTOS_HZ=100 → 1000`（回归项目意图）；
  2. `microros_task.cpp`：`spin_once(10) → spin_once(50)`（rcl_wait 超时 > 定时器周期，避免等值超时分支）。
- 烧录后预期：`DIAG ticks≈500/5s`、`/imu≈100Hz`、odom≈50、scan≈10、battery≈10。
