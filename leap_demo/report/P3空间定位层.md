在**不修改** Cartographer / Nav2 / YOLO 网络 / P2 节点的前提下，新增唯一逻辑节点
`semantic_localizer`，形成完整链路：

## 3. 几何模型

### 3.1 坐标与旋转

- `R_N`：无俯仰相机的光轴基向量在 base 中（右=(0,-1,0)、下=(0,0,-1)、前=(1,0,0)）。
- `Q = Rz(yaw) · Ry(pitch_down) · Rx(roll)`（绕 base 轴的刚体外旋）；`R_base←opt = Q · R_N`。
  pitch_down>0 即光轴下俯（本例 10°）。

### 3.2 像素 → 地面点

```
(u,v) = (bottom_x, bottom_y)
(xn, yn) = cv2.undistortPoints(u,v)          # radtan 去畸变 → 归一化坐标
ray_opt   = (xn, yn, 1)                      # 相机 optical 坐标下的射线
D_base    = R_base←opt · ray_opt             # 射线方向（base 系）
O_base    = (0.06, 0.0, 0.12)                # 相机光心（base 系）
λ = (ground_z - O_base.z) / D_base.z         # 需 D_base.z < 0（目标在地平线下）且 λ>0
P_base    = O_base + λ·D_base → (x, y, 0)
P_map     = T_map←base_footprint(stamp) · P_base
```

无效分支（不崩、记录）：无内参、`D_base.z >= 0`（地平线以上/无交点）、TF 查询超时（先查检测时刻，失败回退最新）→ `ray_valid=false` + reason。

## 4. 节点/接口设计

新包 `xuegeros_ws/src/xuegecar_localizer/`（结构仿 xuegecar_yolo，ament_python，含标准 `setup.cfg`）。

### 4.1 话题与 QoS

| 方向 | 话题 | 类型 | QoS |
|---|---|---|---|
| 订阅 | /semantic/detections | std_msgs/String(JSON) | reliable depth 10 |
| 订阅 | /camera/camera_info | sensor_msgs/CameraInfo | transient_local reliable（仅 source=topic） |
| 订阅 | TF map←base_footprint | /tf | — |
| 发布 | /semantic/objects_localized | std_msgs/String(JSON) | reliable depth 10 |
| 发布 | /semantic/localization_markers | MarkerArray | reliable depth 10 |
| 发布 | /camera/camera_info | CameraInfo | transient_local + 每 5s 重发（source=file） |

camera_info 策略：`camera_info_source=file`（默认）→ 解析 `config/camera_info_ov3660.yaml`（Kalibr 嵌套格式，兼容平铺格式），节点自持发布并内部使用；`=topic` → 订阅上游（如 leap_camera_bridge）。

### 4.2 主要参数（config/semantic_localizer.yaml）

| 参数 | 值 |
|---|---|
| detections_topic / objects_topic | /semantic/detections / /semantic/objects_localized |
| markers_topic | /semantic/localization_markers |
| camera_info_source / camera_info_file | file / .../camera_info_ov3660.yaml |
| camera_frame_id | camera_link（与上游图像帧一致） |
| output_frame / ground_frame / ground_z | map / base_footprint / 0.0 |
| camera_mount_x/y/z | 0.06 / 0.0 / 0.12 |
| camera_yaw_deg / camera_pitch_down_deg / camera_roll_deg | 0 / 10.0 / 0 |
| use_distortion / tf_timeout_s | true / 0.1 |
| **auto_scale_intrinsics** | **true（新增，2026-09-10）**：推流分辨率与标定分辨率不一致时按比例缩放 fx/fy/cx/cy，见 §10 |
| publish_markers | true |

## 9. 修订：地面 z 基准问题（2026-09-09，P4 联动）

现象：真机放地瓶子输出 `position_map.z≈-0.076`（期望 0）。

定位：与内参无关（内参只影响 u,v→x,y/距离）；P3 交点 z 恒等于 ground_frame 的 ground_z，再做 map 变换，因此 `position_map.z` ≡ map 系中 base_footprint 高度。-0.076 恰为 URDF `base_joint z=0.076`，表明 live TF 把 map/odom 平面锚在底盘 base_link 高度。

修复：新增参数 `output_ground_z`（默认 0.0，config/semantic_localizer.yaml 已声明）。求交仍在 base_footprint 地面（保证 x/y/距离不变），`position_map.z` 按语义地面归一输出。

验证（domain42，odom→base_footprint z=-0.076）：bottom(403,288)→ map{x:0.999,y:0.002,z:0.0} dist 0.999；bottom(403,420)→ map{x:0.333,y:0.001,z:0.0}。与 z=0 基线 x/y 完全一致，PASS。

真机待办：P1 在线时 `ros2 run tf2_ros tf2_echo map base_footprint` 复核高度；若确为 -0.076，建议将 P1 odom/SLAM 平面锚点修正到路面（兜底参数与正确 TF 双保险，不会双计）。

## 10. 修订：图像分辨率 ≠ 标定分辨率（2026-09-10 真机联调）

**现象**：现场把瓶子摆在车正前方，P5 却说"目标在旁边 / 已经在它旁边"，而 YOLO 画面里瓶子确实在正前。

**根因**：`camera_info_ov3660.yaml` 写死 SVGA **800×600**（`fx=456.28, fy=454.59, cx=403.86, cy=309.56`），但 MJPEG 推流分辨率是在相机板子上配置的（`http://192.168.31.227:81/`），二者不保证一致。而 `semantic_localizer` 拿到 `/semantic/detections` JSON 里的 `image_width/image_height` 后**只转抄进输出、既不比对也不缩放内参**：

```python
width = int(data.get('image_width', 0))     # ← 旧代码：只转抄
```

若实际是 640×480（或 1280×720），用 800×600 的 `cx/fx` 去解释像素：正前方的目标会被算成**偏 10°~30° 的侧向目标**，距离也系统性错。离线单测量化：同样的地面点，640×480 帧配未缩放内参，反算误差 **>5 cm**，部分位置射线甚至打不到地面（`None`）。

**修法**：
1. `localizer_math.scale_intrinsics(K, cal_dims, image_dims) -> (K', sx, sy)`：纯函数，按 `sx=W/800, sy=H/600` 缩放 `fx/fy/cx/cy`；**radtan 畸变系数是归一化量，不缩放**。
2. `semantic_localizer` 新增参数 `auto_scale_intrinsics: true`：每帧按检测里的 `image_width/height` 取（带缓存）缩放后的 K；宽高比差异 >5% 时打 **ERROR**（说明不是等比缩放而是裁切，缩放只是近似），否则打一次 WARN 提示去更新标定文件。
3. 输出 JSON 增加现场自检字段：`calib_width / calib_height / intrinsics_scaled / intrinsics_fx / intrinsics_cx`。

**测试**（`test/test_localizer_math.py`，7 例，pytest 与 `unittest discover` 均可跑）：
- `test_ground_round_trip_at_calibration_resolution`：已知地面点 → 投影 → 反投影，误差 < 1e-5 m；
- `test_rescaled_intrinsics_recover_the_same_ground_point`：**同样场景换成 640×480 + 缩放内参，反投影结果一致**（这就是修复本体）；
- `test_unscaled_intrinsics_are_off_by_more_than_five_centimetres`：不缩放时误差 > 5 cm（或射线打不到地面），把 bug 钉死在测试里。

> 现场核对：`ros2 topic echo --once /semantic/detections | head -30` 看 `image_width/image_height`；若与 800×600 不同，看 P3 日志里的 `intrinsics rescaled ...` WARN（有 WARN 说明修复已生效，但**建议直接把标定文件的分辨率与内参更新为实际值**，省掉每次缩放）。

**节点级冒烟（ROS_DOMAIN_ID=44，假 TF + 假检测，2026-09-10 实测）**：把一帧 `image 640x480`、瓶子在画面横向中心（`bottom_x=322, bottom_y=300`）的检测喂给 `semantic_localizer`：

```
[WARN] image 640x480 != calibration 800x600 -> intrinsics rescaled by (0.800, 0.800):
       fx=365.0 cx=323.1 fy=363.7 cy=247.6. Update camera_info_ov3660.yaml ...
输出 JSON: image 640x480 calib 800x600 scaled=True fx=365.0 cx=323.1
objects[0].position_base_footprint = {x: 0.425, y: 0.001, z: 0.0}   ← 正前方 y≈0 ✓
```

若不缩放内参，同一个像素会算成 `y ≈ −0.14 m`（约 10° 偏右）——这正是"瓶子在正前方、地图却说在旁边"的来源。证据：`~/xuegeros_ws/log/p5_evidence/p3_intrinsics_rescale_smoke.log`。
