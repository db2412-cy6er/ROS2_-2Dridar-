## 1. 目标与验收链路

```
P3 /semantic/objects_localized（含 num_objects:0 空帧，天然连续）
        |  同类别最近邻 + 一帧一对一数据关联
        |  min_hits=3 连续命中  -> tentative -> confirmed -> ADD 事件
        v
  bottle_001 / bottle_002 ...  （position_alpha EMA 持续更新坐标）
        |  视野门控负观测：仅当目标旧位置当前在相机有效视野带内，
        |  未检出才算 1 次 miss；confirmed 连续 delete_misses=8 帧  -> REMOVE 事件
        v
/semantic/dynamic_map (JSON)  +  /semantic/dynamic_markers (RViz)  +  /semantic/events
```

核心保证：**机器人转到别处 → 原目标不消失、miss 不增长；转回来看见 → 同 id 继续更新；瓶子真被拿走 → 视野内连续多帧空检测后删除**。

### 1.1 空检测帧输入的事实核对（P2/P3 零改动依据）

- P2 `yolo_detector.py`：对**每一帧**发布 `/semantic/detections`（`num_detections` 可为 0）；
- P3 `semantic_localizer.py`：对**每条检测消息**回发 `/semantic/objects_localized`（`num_objects` 可为 0）。

→ 全链路运行时空帧自动连续，负观测按“收到的 P3 帧数”计数（非墙钟），与需求口径一致；P2/P3 无需为 P4 加心跳。

## 3. 状态机与数据关联

- 新检测（置信≥min_confidence、ray_valid、position_map 有效）→ 与**同类别**历史轨迹做最近邻配对，配对按距离升序、一对一（一测量一轨迹，互不复用），避免一帧两瓶同时融到同一轨迹；
- 命中则 EMA 更新 x/y，miss_count 清零；未命中且当前在视野带内 → miss_count++、hit_streak 清零；
- tentative：hit_streak≥min_hits → confirmed + `ADD`；miss≥tentative_delete_misses → 静默删除；
- confirmed：miss≥delete_misses → `REMOVE` + 从 dynamic_map/Marker 消失；
- 视野判定：`robot_yaw(+yaw_offset)` 指向目标的**方位角**是否 ≤ 0.4×HFOV，且距离 ∈[0.25,2.5]m。出视野帧不计 miss，因此转走不删。

## 4. 设计修正点（相对初始方案的查漏补缺）

1. **tentative 无限累积 → 超龄清理**：仅从未确认的轨迹，在最后可见超过 `tentative_max_age_s` 后被定期清理（发 `DISCARD`）。确认目标**绝不做时间清理**（这正是“出视野不删”的核心规则），只走视野门控 miss 删除。
2. **同帧重复检测建双目标 → 同帧去重**：同帧同类别、距离≤association_distance 的多测量只保留高置信一条。
3. **视野切换时序**：测试发现 yaw 突变后若立刻发空帧，会因 TF 未送达按旧朝向误计一次 miss；属测试台架问题，真机 TF 由 P1 连续发布不受影响（报告保留该经验供联调用）。
4. **camera_info 到位后打日志**确认 FOV 生效。
5. **打包**：setup.cfg 含 `[install] install_scripts=$base/lib/<pkg>`（与 P3 同口径）；package.xml 补齐 launch/launch_ros/ament_index_python exec 依赖。

## 6. z=-0.076 BUG 分析与修复（P3 配套小改）

现象：地上瓶子 position_map.z≈-0.076 而非 0。

结论：**与内参无关**。P3 交点 z 恒等于 ground_frame(base_footprint) 的 ground_z=0，再整体变换到 map，故 `position_map.z` ≡ map 系中 base_footprint（地面）的高度；-0.076 恰等于 URDF `base_joint z=0.076`，说明真机 live TF 中 map/odom 平面被锚在底盘 base_link 高度而非路面（P1 垂直基准问题）。

修复（P3）：新增参数 `output_ground_z`（默认 0.0），求交仍在 base_footprint 保证 x/y/距离物理正确，`position_map.z` 按语义地面归一再输出。数学保证：两平行水平面求交仅 z 平移、x/y 不变。

验证：domain 42 构造 `map→odom(0,0,0)` + `odom→base_footprint(0,0,-0.076)`，喂 bottom(403,288)/bottom(403,420)：

```
base={x:0.999,y:0.002,z:0} map={x:0.999,y:0.002,z:0.0} dist=0.999
base={x:0.333,y:0.001,z:0} map={x:0.333,y:0.001,z:0.0} dist=0.333   → PASS
```

真机待办：P1 在线时 `ros2 run tf2_ros tf2_echo map base_footprint` 确认 base_footprint 高度；若确为 -0.076 建议把 P1 平面锚点修到路面（此时 P3 归一与 TF 双保险一致，不会双计）。

## 10. 修订：同帧去重与跨帧关联拆成两个门限（2026-09-10 真机联调）

**现象**：现场在车前方摆**两个**瓶子，摄像头与 YOLO 都明确画出两个框，但 P5 数"前方有几个瓶子"只数到 **1 个**。

**根因**：`association_distance: 0.25` **一处两用**——既做**跨帧**同类别关联，又做**同帧**同类别去重：

```python
# 同帧去重（旧）
self.distance(m['x'], m['y'], c['x'], c['y']) <= self.association_distance   # 0.25
# 跨帧关联（旧）
if d <= self.association_distance:
```

而 P3 的位置是**单目地面交点**：1 m 处约 1.8 cm/像素、**2 m 处约 7.4 cm/像素**（`d = z/tan θ`，误差随距离平方放大）。同帧里两个前后相距 20 cm 的瓶子，估计位置很容易落进 25 cm 门限 → 被合并成一个轨迹。

**修法**（门限分离，语义更清楚）：
| 参数 | 旧 | 新 | 作用 |
|---|---|---|---|
| `same_frame_dedupe_distance` | 无（借用 0.25） | **0.05 m** | 同一帧内的同类别去重。同帧的两个框本来就是两个物体（同一物体的重复框已被 YOLO NMS 压掉），门限只需防止"同一测量被数两次" |
| `association_distance` | 0.25 | **0.15 m** | 跨帧关联。太大 → 两个瓶子被合并；太小 → 同一个瓶子因测距噪声分裂成两条轨迹。0.15 是两者的折中 |

启动日志会打印 `same_frame_dedupe=0.05 assoc=0.15` 便于现场确认。

**回归**：P5 离线场景 **S20**（读**已安装**的 P4 yaml，断言 `same_frame_dedupe_distance ≤ 0.06` 且严格小于 `association_distance ≤ 0.15`），防止以后有人把门限调回一个大值。

> 现场核对：`ros2 topic echo --once /semantic/dynamic_map | head -40`，确认 `objects[]` 里两个瓶子都在（各自的 `id/x/y/relative_position`）。若仍只有一个，再看 P3 输出 `/semantic/objects_localized` 的 `num_objects` 是不是 1——那是检测/投影问题，不是关联问题。
